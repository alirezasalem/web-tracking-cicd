# remove_from_cart

Tracks when a user completely removes an item from their shopping cart.

## Overview

This event fires when a customer clicks the remove button to delete an item entirely from their cart on the cart page. It captures the removed product details along with cart value snapshots before and after removal. This data helps the business understand cart abandonment patterns, identify products that are frequently removed, and optimize the checkout experience.

## Trigger Rules

- User clicks an element matching `[data-testid="remove-item-btn"]` on the `/cart` page
- User must be on the cart page (`/cart`) — do not fire on mini-cart or other cart widgets
- Fire only when an item is **completely removed** from the cart, not when quantity is decreased
- Implement click debouncing to prevent duplicate events from rapid clicking (recommend 500ms cooldown per item)
- Do **not** fire when:
  - User decreases item quantity (e.g., from 2 to 1)
  - Item is removed automatically due to out-of-stock status
  - Cart is cleared in bulk via a "Clear Cart" action (handle separately if needed)

## Business Rules & Edge Cases

1. **Deduplication required**: Implement a 500ms debounce per `item_id` to prevent duplicate events when users rapidly click the remove button. Only fire once per removal action.

2. **Complete removal only**: This event tracks full item removal. If a user changes quantity from 3 to 2, that is a quantity update—not a removal. Do not fire `remove_from_cart` for quantity decreases.

3. **Value calculation**: The `value` parameter should reflect the total value of what was removed (`price × quantity`). If removing 2 units at $29.99 each, `value` should be `59.98`.

4. **Cart value snapshots**: `cart_value_before` and `cart_value_after` should be captured from the cart state, not calculated. Ensure these values are read before and after the cart state updates, respectively.

5. **Currency consistency**: All monetary values (`value`, `price`, `cart_value_before`, `cart_value_after`) must use the same currency specified in the `currency` parameter.

6. **SPA considerations**: If the cart page is a single-page app component, ensure the event fires after the removal is confirmed in state/API, not just on button click. This prevents tracking removals that fail due to network errors.
