# purchase

Tracks completed e-commerce transactions when a customer successfully places an order.

---

## Overview

This event fires when a customer lands on the order confirmation page after completing a purchase. It captures the full transaction details including order value, tax, shipping costs, and all items purchased. This is the most critical e-commerce event—it directly measures revenue and conversion success, powering ROI calculations, attribution models, and marketing spend decisions.

---

## Trigger Rules

- The user must land on the `/order-confirmation` page
- The page must fully load (fire on page load, not on click or interaction)
- Transaction data must be available in the data layer before the event fires
- **Deduplication required:** The event must NOT fire again if the user refreshes the confirmation page or navigates back to it
- The event must NOT fire if the transaction data is missing or incomplete (e.g., no `transaction_id`)

## Business Rules & Edge Cases

1. **Deduplication is mandatory:** Store the `transaction_id` in `sessionStorage` or `localStorage` after the first fire. On subsequent page loads, check if this transaction has already been tracked and suppress the event if so. This prevents inflated revenue from page refreshes.

2. **Backend-generated data:** The `transaction_id`, `value`, `tax`, and `shipping` values must come from the backend order confirmation response—never calculate these client-side, as they may differ from actual charged amounts.

3. **Currency consistency:** The `currency` value must match the currency in which the `value` was charged. Do not mix currencies within a single purchase event.

4. **Empty coupon handling:** If no coupon was applied, omit the `coupon` parameter entirely rather than passing an empty string or null.

5. **Items array must not be empty:** Every purchase event must include at least one item in the `items` array. If the items data is unavailable, delay the event until it can be populated.

6. **SPA considerations:** If the order confirmation is rendered via client-side routing (SPA), ensure the data layer push occurs after the transaction data is fully available from the API response, not on route change alone.

7. **GTM implementation:** Use a Page View trigger with a Page Path condition matching `/order-confirmation`. Layer in the deduplication check via a Custom JavaScript variable or Blocking Trigger.
