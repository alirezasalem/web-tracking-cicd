# purchase

Tracks a completed purchase transaction when a customer successfully places an order.

---

## Overview

This event fires when a customer reaches the order confirmation page after completing a purchase. It captures the full transaction details including revenue, taxes, shipping costs, and all purchased items. This is the most critical ecommerce event for measuring conversion value and calculating ROI on marketing spend.

---

## Trigger Rules

- **MUST** fire on page load of the `/order-confirmation` page
- **MUST** only fire once per unique `transaction_id` — implement deduplication to prevent duplicate firing on page refresh or back-button navigation
- **MUST** wait until all transaction data is available in the data layer before firing
- **MUST NOT** fire if the user navigates directly to the confirmation page without completing a purchase
- **MUST NOT** fire for failed or cancelled transactions

## Business Rules & Edge Cases

1. **Deduplication is critical**: Store the `transaction_id` in `sessionStorage` or a cookie after the first fire. On subsequent page loads (refresh, back-button), check if this `transaction_id` has already been tracked and skip firing if it has. Duplicate purchase events will inflate revenue reporting.

2. **Currency formatting**: The `value`, `tax`, `shipping`, and `price` fields must be numeric (not strings). Use decimal notation with up to 2 decimal places. Do not include currency symbols.

3. **Coupon handling**: If no coupon was applied, omit the `coupon` parameter entirely rather than passing an empty string or null.

4. **Items array**: Must contain at least one item. Each item in the order should be represented as a separate object in the array, even if the same product was purchased multiple times (use `quantity` to reflect count).

5. **Value calculation**: Ensure `value` represents the actual amount charged to the customer. Clarify with your analytics team whether this should include or exclude tax and shipping based on your reporting requirements.

6. **SPA consideration**: If the order confirmation is rendered client-side in a single-page application, ensure the data layer push occurs after the order data has been fetched and rendered, not on route change alone.
