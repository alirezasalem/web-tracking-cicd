# add_to_cart

Tracks when a user successfully adds a product to their shopping cart.

## Overview

The `add_to_cart` event fires when a user clicks an add-to-cart button and the product is successfully added to their cart state. This event is critical for understanding product interest, measuring add-to-cart conversion rates, and identifying friction points in the shopping funnel. It powers funnel analysis from product discovery through purchase completion.

## Trigger Rules

- User clicks an element matching `.add-to-cart` or `[data-action='add-to-cart']` on any product page (`/products/*`)
- The cart state validation must complete successfully **before** the event fires
- Do **not** fire on button click alone — wait for confirmation that the item was actually added to the cart
- Do **not** fire if the cart API returns an error or the product is out of stock
- Do **not** fire duplicate events if the user rapidly clicks the button multiple times for the same action

## Business Rules & Edge Cases

1. **Fire after validation, not on click**: Use a custom event trigger in GTM that listens for the `add_to_cart` dataLayer push. Do not bind directly to button click events, as this would fire before cart state is confirmed.

2. **Clear previous ecommerce data**: Always push `{ ecommerce: null }` immediately before the event to prevent stale data from previous ecommerce events from bleeding into this hit.

3. **Price formatting**: Send `price` and `value` as raw numbers without currency symbols. Use periods for decimal separators regardless of locale (e.g., `49.99` not `49,99`).

4. **Value calculation**: The top-level `value` parameter should equal `price × quantity`. For a single item at $49.99 with quantity 2, send `value: 99.98`.

5. **Quantity must be a positive integer**: Never send zero or negative quantities. If a user removes items, use the `remove_from_cart` event instead.

6. **SPA considerations**: On single-page applications, ensure the event fires on each add-to-cart action even if the user doesn't navigate away from the page. Bind to the cart update callback, not route changes.
