# add_to_cart

Tracks when a user successfully adds a product to their shopping cart.

---

## Overview

This event fires when a user adds an item to their cart on any product page. It captures the product details, quantity selected, and variant information to enable analysis of add-to-cart behavior, conversion funnel performance, and product popularity. This data is critical for understanding which products drive engagement and where users drop off before purchase.

---

## Trigger Rules

- User clicks an element matching `.add-to-cart` or `[data-action='add-to-cart']` on any page under `/products/*`
- The cart state validation must complete **successfully** before the event fires (do not fire on button click alone)
- The product must have valid `product_id`, `product_name`, and `price` values available
- Do **not** fire if the cart validation fails or returns an error
- Do **not** fire multiple times for the same add action (wait for validation response before allowing another push)

## Business Rules & Edge Cases

1. **Fire after validation, not on click**: The GTM trigger must listen for the `add_to_cart` dataLayer push event, not the direct button click. Only push to dataLayer after the cart API confirms the item was added successfully.

2. **Clear ecommerce object first**: Always push `{ ecommerce: null }` before the event to prevent data from previous ecommerce events bleeding into this hit.

3. **Value calculation**: The `ecommerce.value` field should reflect the total value added (`price × quantity`), while `items[].price` remains the unit price.

4. **Currency format**: Use three-letter ISO 4217 codes (e.g., `USD`, `EUR`, `GBP`). Do not include currency symbols.

5. **Price as number**: Pass `price` and `value` as numeric types, not strings. Use `79.99` not `"79.99"` or `"$79.99"`.

6. **Category hierarchy**: Use forward slashes to separate category levels (e.g., `"Apparel/Mens/T-Shirts"`). Keep consistent across all events.

7. **Quantity must be positive integer**: Always pass a whole number ≥ 1. If the user adjusts quantity before adding, capture the final quantity selected.
