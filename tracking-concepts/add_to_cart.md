# add_to_cart

Tracks when a user successfully adds a product to their shopping cart.

---

## Overview

This event fires when a customer adds an item to their cart from a product page. It captures the product details, quantity selected, and price at the moment of addition. This data is critical for understanding purchase intent, identifying popular products, and powering remarketing campaigns for cart abandoners.

---

## Trigger Rules

- User clicks an element matching `.add-to-cart` or `[data-action='add-to-cart']` on any page under `/products/*`
- The cart state must be successfully validated **before** the event fires — do not fire on the button click itself
- The dataLayer push should occur only after the cart API confirms the item was added
- Do **not** fire if the add-to-cart action fails (e.g., out-of-stock error, network failure)
- Do **not** fire multiple times for a single user action (debounce rapid clicks)

## Business Rules & Edge Cases

1. **Fire after validation, not on click**: The GTM trigger must listen for the `add_to_cart` dataLayer push event, not the button click. The push should only happen after the cart API confirms success.

2. **Clear ecommerce object first**: Always push `{ ecommerce: null }` immediately before the event to prevent stale data from previous ecommerce events bleeding into this hit.

3. **Price is unit price**: The `items[].price` field should reflect the single-unit price. The `ecommerce.value` field should be the calculated total (`price × quantity`).

4. **Currency consistency**: Use the same ISO 4217 currency code (`USD`, `EUR`, `GBP`, etc.) across all ecommerce events in a session.

5. **Variant formatting**: If multiple variant dimensions exist (e.g., color and size), concatenate them with a consistent delimiter like ` / ` (e.g., `Black / Large`).

6. **Quantity updates**: If a user adds the same item that's already in their cart, fire this event with the incremental quantity added, not the new cart total for that item.
