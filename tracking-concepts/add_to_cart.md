# add_to_cart

Tracks when a user successfully adds a product to their shopping cart.

## Overview

This event fires when a visitor adds an item to their cart from a product page. It captures the product details, quantity selected, and pricing information to measure add-to-cart conversion rates and understand which products generate the most purchase intent. This data helps optimize product pages and identify high-performing items.

## Trigger Rules

- User clicks an element matching `.add-to-cart` or `[data-action='add-to-cart']` on any page under `/products/*`
- The event must fire **after successful cart state validation**, not immediately on button click
- The cart must successfully update before pushing to dataLayer (wait for API confirmation or state change)
- Do NOT fire if the cart update fails or the product is out of stock
- Do NOT fire on duplicate rapid clicks for the same product (implement debouncing if needed)

## Business Rules & Edge Cases

1. **Fire after validation, not on click**: The GTM trigger must listen for the `add_to_cart` dataLayer push event, not the button click directly. Developers should only push this event after confirming the cart state has updated successfully.

2. **Currency consistency**: The `currency` value must match the currency displayed to the user. Use ISO 4217 three-letter codes (USD, EUR, GBP, etc.).

3. **Value calculation**: The `ecommerce.value` field should equal `price × quantity` for the item being added. For a single item at $79.99 with quantity 2, value should be `159.98`.

4. **Price formatting**: Always use numeric values for `price` and `value`, not strings. Do not include currency symbols or thousand separators.

5. **Variant formatting**: Combine multiple variant attributes into a single string using a consistent delimiter (e.g., `Color / Size`).

6. **SPA considerations**: On single-page applications, ensure the ecommerce null-clear push happens before every add_to_cart event to prevent stale data from previous interactions.
