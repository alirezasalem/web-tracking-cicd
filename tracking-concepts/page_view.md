# page_view

Tracks when a user views a page, whether on initial site load or when navigating within a single-page application (SPA).

---

## Overview

The `page_view` event fires every time a user lands on a new page or navigates to a different view within the application. This is the foundational event for understanding user journeys, measuring content engagement, and analyzing traffic sources. It captures where the user came from, what page they're viewing, and basic device information to enable audience segmentation.

---

## Trigger Rules

- **Initial page load**: Fire when the DOM is fully ready on any page across the site
- **SPA navigation**: Fire when the browser history changes (e.g., user clicks an internal link that updates the URL without a full page reload)
- The event must fire on every unique page path—there is no path restriction
- Do not fire multiple times for the same page view (e.g., if both DOM Ready and History Change fire on initial load, deduplicate to one event)
- Do not include personally identifiable information (PII) in the `page_location` parameter—filter out query parameters containing emails, tokens, or other sensitive data before pushing

## Business Rules & Edge Cases

1. **PII filtering**: Before pushing `page_location`, strip any query parameters that may contain PII (e.g., `?email=`, `?token=`, `?resetCode=`). Use a whitelist approach if possible—only pass known-safe parameters.

2. **SPA deduplication**: On single-page applications, ensure the event fires exactly once per navigation. If your framework triggers both a DOM Ready and a History Change on initial load, implement logic to prevent duplicate events.

3. **GTM trigger configuration**: Configure GTM to fire this tag on both "DOM Ready" and "History Change" triggers to capture traditional page loads and SPA navigations.

4. **Empty referrer handling**: For direct traffic or when the referrer is unavailable, pass an empty string (`""`) rather than `null` or `undefined`.

5. **User ID availability**: The `user_id` should only be populated after the user has successfully authenticated. For anonymous users, either omit the parameter or set it to `null`.

6. **GA4 custom dimensions**: The `user_id` maps to `cd_user_id` and `device_type` maps to `cd_device_type` in GA4. Ensure these custom dimensions are configured in your GA4 property.
