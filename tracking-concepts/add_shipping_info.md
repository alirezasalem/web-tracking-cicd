# add_shipping_info

Tracks when a user successfully saves their shipping method selection during checkout.

## Overview

This event fires after a user selects a shipping option (e.g., Standard, Express, Overnight) and the backend validates the shipping information. It captures the chosen shipping tier along with the current cart value and items. This data helps the business understand shipping preference patterns, identify where users drop off in checkout, and optimize shipping tier offerings based on actual usage.

## Trigger Rules

- The user must be on the `/checkout/shipping` page
- The user must click the "Continue to Payment" or "Save Shipping" button (exact selector TBD)
- The shipping validation API must return a **200 success response** before firing
- Do **NOT** fire on button click alone — wait for backend confirmation
- Do **NOT** fire if the API returns an error or validation failure
- Do **NOT** capture any address details, names, or contact information (PII restriction)

## Business Rules & Edge Cases

1. **Fire on API success only**: Do not fire this event when the user clicks the button. Wait for the shipping validation endpoint to return a 200 response, then push to dataLayer.

2. **PII restriction**: Only capture the `shipping_tier` string (e.g., "Standard", "Express"). Never capture street addresses, recipient names, phone numbers, or any other personal information.

3. **Empty coupon handling**: If no coupon is applied, pass an empty string (`""`) rather than `null` or omitting the field.

4. **Currency formatting**: Always use 3-letter ISO 4217 codes (e.g., `USD`, `EUR`, `GBP`). Do not include currency symbols.

5. **Value precision**: Use decimal numbers with up to 2 decimal places. Do not include currency symbols or thousand separators in the `value` field.

6. **SPA navigation**: If the checkout is a single-page app, ensure the dataLayer push happens after the shipping API response resolves, not on route change.

7. **Selector clarification needed**: The exact button selector for "Continue to Payment" or "Save Shipping" requires confirmation from the frontend team before implementation.
